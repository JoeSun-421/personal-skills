# Papers, Web Articles, and Authored Writing

## Inspect and Deduplicate

Read the destination library's instructions, README, topic folders, and logs before adding a source. Use its current organization. For a new library, a thematic index is a useful default; use dated batches only if the user or active library requires them.

Identify a paper by arXiv ID, DOI, or normalized title and authors. Identify a web article by canonical URL and title. Search existing indexes and files before downloading. Versions of one paper belong to one source record: preserve an older artifact when provenance matters, and label a new version rather than silently replacing it.

Save one canonical copy per source. Cross-topic reading uses index links, not duplicated PDFs. Preserve original filenames unless a rename is requested or necessary; if renaming, update links and record the mapping.

## Obtain and Validate

Prefer primary sources and the exact relevant version. Use current official pages to verify title, authors, dates, version, and links. Record access limits rather than inventing missing content.

For a PDF, check HTTP content type, the `%PDF-` signature, file type, successful parsing/page count, and title/version where available. Do not save a login page or HTML error response with a PDF extension. Use supported existing download routes; after a failed route, try a permitted fallback and stop if the actual artifact cannot be validated.

For a web source, retain the canonical URL, title, author when identified, publication/update date when available, and actual access date. Save a local capture only when requested or useful and permitted; distinguish it from the live source.

Index every saved artifact. Record source ID/URL, version, topic, local path, acquisition date, and validation status. Include checksums and page counts when useful for provenance or migration. Date new records using the user's current timezone, Asia/Hong_Kong unless overridden.

## Reading and Translation Status

Keep these states distinct:

| Artifact/state | What it establishes |
| --- | --- |
| Downloaded original | The source exists locally and passed stated file checks |
| Reading note | An interpretation of the portions actually read, with section/page references |
| Full translation | A complete translation of the stated source version, including its required checks |
| Summary | A shortened account, never a substitute for a required full translation |
| Draft article | The user's authored explanation, with its own argument and sources |

Follow the target library's current translation requirements. If the user requests download only and translation is deferred, state that in the index/log and final delivery. If full archival compliance requires a translation and mathematics checker, complete those checks or explicitly report the remaining gap. Do not import an old retired archive's translation or date-folder requirements into every new project.

Keep original PDFs unchanged. Place notes, translations, and extracted figures beside the relevant source or in the library's established linked note/asset paths. Mark hypothetical examples and new derivations.

## Add an Authored Article

Store the article in the user's chosen blog or notes directory under the workspace, with stable links to local figures and source records. Add it to the appropriate project index rather than creating a second paper entry for it.

Use the available technical writing skill for substantial drafting or rewriting. Preserve the user's voice, mixed-language wording, and equations unless the request calls for translation or technical correction. Record technical corrections affecting meaning with their evidence.

A local blog draft, a rendered preview, and a published site are distinct deliverables. Do not publish, change hosting, or message readers unless requested. Link to shared derivations and figures rather than copying them into every weekly report or meeting note.

## Reorganize Without Loss

Before moving an existing library, record old/new paths, stable source identifiers, hashes, and permissions. Preserve original documents and notes. Repair and check local links in indexes, notes, and article drafts. Report exactly which files moved and which files changed content.
